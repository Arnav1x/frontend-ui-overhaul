# Milestone 07: Test-Document Action Capture

**Status:** Complete

## Objective

Capture confirmed Browser Execution Agent actions into a simple, export-neutral
intermediary test document. Each captured step retains its action, CSS selector
when available, Playwright locator, and parameter where needed. The document is
not an executor queue, agent plan, or final export.

## Outcome

Completed Agent Testing Console runs now expose one ordered intermediary step
for each confirmed user-visible action. Click and fill steps retain the
Playwright locator generated by local Playwright MCP and a validated CSS
selector for the exact element acted on. Parameters remain masked in the
developer console by default.

## Implementation History

- Captured successful `navigate`, `click`, and `fill` action facts into a
  run-local, in-memory intermediary document. `fill` preserves its entered
  parameter; descriptions are deliberately permitted to remain empty.
- Extracted Playwright locators from local MCP `Ran Playwright code` output.
- Added product-owned selector capture behind `BrowserSession`, using a fixed
  DOM evaluation against the exact current snapshot target before each click
  or fill. Each CSS candidate must be unique and resolve back to that same
  element.
- Normalized an agent-supplied snapshot display label containing `[ref=...]`
  to its reference token before selector capture and browser execution, while
  retaining both forms in the diagnostic trace when they differ.
- Added MCP-result parsing for both fenced JSON and the current `### Result`
  section, excluding following Playwright diagnostic sections. Unparsed
  successful evaluator output remains visible in the developer trace rather
  than producing an invented selector.
- Established selector policy: unique IDs and test attributes first, then
  `name`/ARIA attributes and host-independent HTTP(S) link routes; descriptive
  titles and structural CSS remain lower-confidence fallbacks.
- Updated the Agent Testing Console to display the captured document and
  selector-capture diagnostics without claiming capture is still pending.
- Added a simple selector strategy to each captured selector: `id`,
  `attribute`, `link-route`, or `structural-fallback`.

## Verification Evidence

- `npm run format`, `npm run typecheck`, `npm test`, and `npm run lint` passed.
  The final suite contained 25 Vitest files / 79 tests and 10 Node script tests.
- User live testing confirmed the five-step alternate-credentials workflow:
  1. Alternate-login link: `#ContentPlaceHolderTop_alternate_login_link`
  2. Username fill:
     `#ContentPlaceHolderTop_GlobalLogin_GlobalLoginView_GlobalLogin_UserName`
  3. Password fill:
     `#ContentPlaceHolderTop_GlobalLogin_GlobalLoginView_GlobalLogin_Password`
  4. Login click:
     `#ContentPlaceHolderTop_GlobalLogin_GlobalLoginView_GlobalLogin_Login`
  5. PPM click: `a[href$="/DAIT/SPM/"]`

  Each step also contained its matching Playwright locator. Credential
  parameters were masked in the displayed document.

## Findings

- CSS selector validity and selector stability are different properties.
  Exact-element uniqueness validation prevents mis-targeting, while the
  candidate policy avoids preferring verbose copy-based titles over stable
  application routes.
- The shared selector-capture engine belongs at the `BrowserSession` boundary,
  so a future Manual Recording workflow can use the same DOM inspection and
  validation path.
- Playwright MCP may append diagnostic sections after evaluation output;
  product parsing must isolate the structured result rather than assume the
  whole tool response is JSON.
